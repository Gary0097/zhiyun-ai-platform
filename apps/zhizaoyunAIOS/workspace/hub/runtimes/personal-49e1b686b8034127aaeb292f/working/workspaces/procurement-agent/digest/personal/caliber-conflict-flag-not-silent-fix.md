# 口径冲突处置约定（文档定义与数据实现不一致时沿用现状并标注待复核）

**Rule**：当知识库口径文档（《业务口径_供应商评估与补货.md》《字段字典_采购扩展.csv》）与数据库视图的实际逻辑不一致时，交付清单沿用数据库现有状态、不擅自改判；冲突单独成节标注"待复核"，并给出按文档口径重算后的差异清单。发现即标注，不静默修正。

**Why**：改判权在口径 owner 一侧，助手单方面"顺手修正"会让实现缺陷被掩盖、复核者无法复现结论；而"复合条件只落地一个分支"这类偏差会系统性低估风险，必须显式暴露而不是吸收掉。

**How to apply**：每次出单前先把"文档定义 vs 视图实际逻辑"当检查点验一遍。实例：文档定义紧急 = 可用天数 < 5 天 或 库存 < 阈值×50%，快照只执行了 <50% 分支，导致 M01（3.9 天 / 51.1%）与 M06（3.6 天 / 54.5%）漏升级为紧急——本次仍按数据库状态出单，另设冲突节说明按文档应升级。该纪律在算法链里的落点见 [[digest/procedure/replenishment-advice-calculation-runbook.md|补货建议量计算 runbook]] 的"沿用现有预警状态、分歧单列待复核"一步；它与 [[digest/wiki/recommendation-confidence-downgrade.md|推荐可信度降级原则]] 同属一族——都把"系统结论"与"助手判断"分离标注。漏升级紧急会连带压低 [[digest/wiki/lead-time-gap-principle.md|交期缺口原则]] 所要求的加急动作优先级，判定口径尤其值得先验。门槛与价格校验本身按 [[digest/procedure/supplier-recommendation-triple-gate.md|供应商推荐三重门控]] 执行，不在擅自改判范围内。
