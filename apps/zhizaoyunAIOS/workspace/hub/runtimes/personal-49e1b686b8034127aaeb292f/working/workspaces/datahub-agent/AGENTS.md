# AI数据中枢智能体 · 工作区规则

## 职责

金汉隆六项数据分析能力：①实时客户订单进度看板 ②客户交付风险预警 ③多源数据自动采集 ④跨部门数据融合指标 ⑤每日08点经营简报 ⑥关键指标趋势分析。

## 数据双通道（务必区分）

1. **知识库（找事实 / 口径）**：`python3 datahub/scripts/kb_search.py "问题"` 检索《金汉隆-数据中枢》（30张表全量数据 + 字段字典 + 业务口径）。
2. **计算副本（算数字）**：`python3 datahub/scripts/query.py "SELECT ..."` 对 `datahub/agent_data.sqlite` 只读查询；统计/回归用 `python3 datahub/scripts/calc.py 1,2,3`。
   - 任何汇总、占比、均值、斜率必须来自 SQL 聚合或 calc.py 的计算结果，禁止凭知识库片段心算全量数字。
3. **库存（2026-09-18 快照，来自《库存表9.18.xlsx》）**：
   - 现状一物料一行：`inventory_snapshot`（库位/物料名称/规格型号/机型/上月库存/当月入出库/当天库存/备货数/库存预警=充足|库存不足|库存归零）。
   - 流水长表：`wms_transactions`（期初结转 + 9月1~18号 入库/出库/返工入仓/返工出仓，signed_quantity 出库方向为负）；当前结存视图 `v_inventory_balance`（应等于当天库存）。
   - 重灌/更新：`python3 datahub/scripts/load_inventory.py <库存表.xlsx>`（幂等；需同步 /data/actions 服务副本时加 `--db`）。
4. **人力资源·入离职（模拟演示数据，2025-01~2026-09）**：
   - `hiring_records` 入职记录（46 条，E052-E097）：岗位/试用期与转正月薪/招聘渠道/试用期结果（转正|试用期离职|试用中）。
   - `turnover_records` 离职记录（24 条，均来自上述新入职段）：司龄月数/离职类型（主动辞职|公司辞退|合同到期不续签）/原因/交接。
   - 口径：期间离职率 = 期间离职 ÷ 期初期末平均在职；试用期离职 ⇔ 离职日期 ≤ 试用期届满日；不影响 employees 现有花名册。
   - 重新生成：`/root/zy-xlsx-venv/bin/python datahub/scripts/gen_hr_turnover.py`（固定种子，幂等）。

## 硬性纪律

- 固定时间从 `configuration.snapshot_at` 读取（= 2026-09-18 08:00 北京时间），不得使用机器当前日期。
- 只分析已生效订单；以 `sales_order_id` / `work_order_id` 关联，**禁止仅按合同号(contract_no)跨表 JOIN**。
- 订单完成 = **全量签收**（分批发货不算完成）；实际时间为空 = 未发生。
- 台 / 套 / 件分别统计；跨产品折算用"标准工时产出"并明确标注。
- **防放大**：先对每张事实表按目标粒度预聚合，再与订单关联；不允许多张事实表直接 JOIN 后 SUM。
- 概率/评分输出必须标注"**交期紧迫度评分，未校准**"；已发生逾期订单单独列出（事实，不包装成预测）。
- 没有证据不编造原因；数量冲突 / 模糊交期 / 无效关联键 → 进入人工复核清单，不静默覆盖。
- 发送动作仅限 Mock 推送接口（`http://127.0.0.1:18765/api/mock/wechat/push`，`WB_MANAGEMENT`）；**禁止真实发信、真实微信推送或写回企业系统**。
- 采集演练：`python3 datahub/scripts/collect.py`（按 transaction_id / event_id 去重，坏样本隔离到 output/，幂等）。

## 输出格式

结论先行；每条结论附：订单号/工单号、时间窗口、单位、原始证据（SQL 语句或知识库文档出处）。
