# 2.2.2 Windows 完整发行与 Hub 转换验收

Issue #164，PR #165，目标版本 `2.2.2-office-1.6.1`。

## 最终实现

原生 Hub 会清洗父进程环境，成员的 PATH 和 Windows AppContainer 只读根也不包含 extras。因此不能只在 Hub 启动器中设置 SOFFICE。完整安装器分别预装单机与 Hub 的办公依赖，将完整 LibreOffice 复制到 Hub venv/aios-libreoffice，在 Hub venv/Scripts 安装转换入口。成员使用原生 PATH 即可发现该入口，不修改 QwenPaw 内核或放宽文件隔离。

转换入口使用官方 LibreOfficeKit 稳定接口。普通桌面入口的进程通信不兼容原生 AppContainer；直接从外部线程调用 LibreOfficeKit 又会让 Windows Impress 等待其窗口线程。最终入口只向本进程的 SALCOMWND 窗口线程派发文档读取、导出和关闭调用，核验窗口所有者 PID，不操作其他应用。

每次转换使用当前 AppContainer 的专属系统存储和独立随机配置目录，避免深层成员目录叠加扩展缓存造成路径过长。独立工作进程退出后，由未加载 Office 的父进程删除缓存，避免扩展缓存句柄未释放。工作进程必须正常返回并写入完成标记，父进程才接受成功；单独的退出码 0 不算成功。超时返回失败。转换进程创建前清除 Hub Python 路径并关闭 GPU 探测，不将 Python 3.12 依赖注入 Office 内置 Python。

入口支持 `--version`、`--headless --convert-to <扩展名> --outdir <目录> <输入文件>`。自定义 CLI 筛选器明确报错，不静默忽略。禁止覆盖输入原件。

LibreOffice 官方二进制未修改。过程中试验过管道命名修订，未通过即撤回；验收副本的官方 sal3.dll 已恢复且数字签名有效，试验文件不进入发行包。

安装完成标记包含依赖、入口和组件指纹；普通启动快速返回，不复制 Office、不运行依赖探测或下载。`setup-ai-os.ps1 -RepairOffice` 将修复请求传递到 Hub，显式修复可恢复嵌套损坏的包文件；使用包内 Node，不要求系统安装 Node。
