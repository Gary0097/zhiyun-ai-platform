# 启动轻量化与模型添加配置验收

Issue #166，基于 `aios-office` 的 2.2.2 办公版。用户确认主要问题是“添加或配置模型太繁琐”。不改 QwenPaw 内核，不改变现有模型、账号和原生权限边界。

## 改动

- 启动器与诊断在同一进程复用已经校验的运行时对象，消除一次重复 CLI 版本探测。独立诊断仍自行验证，未信任环境变量中的版本收据。
- 已确定控制台位置时直接传给品牌补丁，避免再启动 CLI 查找同一运行时；无法确定时仍走原有定位逻辑。Windows 多省一次探测，Linux 保留原有资产定位与语法入口。
- 品牌前端由同步和原生自动发现加载；缺少品牌版本标记也不调用 CLI 重装。没有降低原生登录、版本、Python 导入、目录可写性及端口检查。保留用户禁用插件的原生状态。
- `AIOS_PORT` 支持严格整数端口，默认仍为 8088，用于隔离验收和显式自定义。桌面启动器仍使用默认 8088。
- 品牌插件 1.1.0 增加“模型快配”，通过官方扩展接口和原生模型 API 实现。额外模块按需加载，无新框架依赖，也没有新的服务进程。

## 模型配置路径

原页面需要手写固定提供商 ID，并分别添加服务、配置模型。新入口集中服务名称/地址/密钥、检测连接、获取与搜索列表、手填 ID、全局/智能体应用范围。完整 OpenAI 兼容接口地址会归一为基础地址，拒绝带账号、密钥查询参数或非 HTTP(S) 的地址。

编辑时不回显密钥，留空不清除现有密钥，也不覆盖高级请求头和生成参数。自动发现不重复启动两次。保存失败、发现失败、密钥被拒绝及超时均不冒充成功；已保存但获取失败会明确说明并保留手填路径。内置服务名称只读。

Ollama / LM Studio 使用原生本地提供商，无需伪造密钥。新通用兼容服务仍需要密钥。模型元数据预览端点会给未知 ID 返回预览，因此手填模型用原生选择接口的明确“模型不存在”结果决定是否添加，不能仅凭预览返回 200 判断存在。

## 验收与范围

独立环境端口 18089，独立账号、工作区与密钥；生产 H 盘未覆盖。供应商 HTTP 夹具在 18888/18889，名称明确为合成接口，不能据此宣称实际大模型推理通过。

- 界面实际完成新增兼容服务、粘贴完整地址、获取列表、搜索、设置全局默认与仅当前智能体。
- 原生存储确认全局模型保留为合成 long 模型，而当前智能体独立使用 chat 模型。高级请求头和生成参数保留。
- 故意返回供应商 401，界面明确提示密钥被拒绝；服务保留，允许修复或手填。没有显示服务端原始错误中的敏感内容。
- 免密本地服务获取列表成功。现有 LM Studio 服务 1234 通过原生连接检查；没有以此声称推理通过或修改 H 盘供应商。
- 密钥按原生机制保存，磁盘密文字段不能用明文字符串对比。重启原生服务后再次检查连接和模型配置，结果另记录在本机验收 JSON。
- 纯逻辑测试覆盖地址解析、URL 中凭据拒绝、空密钥编辑保留、高级字段不覆盖、模型元数据限缩、中文错误和安全的自动 ID。
- 启动诊断测试覆盖无效端口、缺失运行时失败、端口被外来服务占用时拒绝且保留外来监听。

2026-10-20 启动对比在同一 Windows 安装、18090 端口、普通用户独立工作区进行；旧版只调整绑定及检查端口。首次准备不计入重复启动，前后保留原生认证和账号。不能把这组隔离环境计时当作 H 盘新计时。

| 指标（秒） | 原版第 1 次 | 新版第 1 次 | 原版第 2 次 | 新版第 2 次 |
| --- | ---: | ---: | ---: | ---: |
| 首次首页 HTTP 200 | 11.208 | 10.145 | 6.088 | 10.017 |
| 默认智能体工作区接口可用 | 11.800 | 10.747 | 11.236 | 10.625 |

完整智能体就绪均值由 11.518 秒降至 10.686 秒，约减少 0.832 秒（7.2%），样本仅两对；首次首页响应明显波动，不能宣称首页稳定提速。上一组三对首页结果为原版 6.124 / 11.247 / 6.139 秒、新版 9.986 / 10.012 / 9.901 秒，同样不能支持首页稳定提速。后台核心初始化可能在首页返回前后完成，首页可访问不等于智能体已就绪；核心未改动。

子进程采样确认 Windows CLI 版本探测从 3 次减至 1 次，单次约 0.45–0.51 秒；原生诊断仍保留。删除隔离环境品牌版本标记后，新版 11.005 秒完成智能体及品牌接口验收，品牌 1.1.0 原生发现成功。最终计时与日志保存在本机忽略目录 `runtime/optimization166/startup-profiled/`，没有放入账号或模型凭据。

复用上一轮管理员隔离验收目录时曾遇到某插件目录的 Windows 访问拒绝，未降低 ACL 权限；改用普通用户创建的全新测试工作区完成以上验收，原验收工作区随后恢复。生产 H 盘未参与此次计时。

`node scripts/verify-release.mjs` 全部门禁通过，包括新增的模型配置逻辑测试、启动诊断测试，以及原有办公依赖、中文路径、安装升级与卸载数据保留检查。

测试过程中曾在已启动的原版资产上应用品牌补丁，浏览器旧缓存造成双入口加载；重启并按安装版“先初始化、后启动”的顺序、使用干净浏览器来源后消失。这不是通过修改核心或关闭认证解决的。日常产品入口在启动服务前完成补丁。

## 交付与回退

Windows 启动链路和原生界面实测；Linux 依赖 CI 与跨平台源代码检查，未冒充 Linux 实机验收。Hub 写入向导未开放，仍用原生管理，不绕过集中供给策略。原生模型激活可能发起后台能力探测，已在界面说明。

变更只涉及启动脚本、品牌前端与文档。回退到上一个 `aios-office` 版本并同步品牌插件即可，保留 workspace、secret 和 Hub 数据。按照仓库分支流程提交 PR 等待审核，不提前替换已发布 1.6.1 安装包或 H 盘程序。
