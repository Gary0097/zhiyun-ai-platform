## 已复现的问题与修复

- 重复品牌补丁会匹配已注入脚本注释中的 HTML 结束标签，导致主题进入脚本内部。现在在真正的 head 结束位置插入，重复应用测试检查样式仍位于脚本外。
- 深色系统主题下，白色登录背景与白色标题/安全提示混用。登录页现在完整采用浅色样式，已登录页面保持原主题。
- 两层 `.qwenpaw-app` 同时分栏，低高度窗口裁切。现在仅外层 Spark 容器分栏，登录根节点允许纵向滚动。真实 Hub 在 900×500 和 320×568 下检查，320px 下输入宽度约 229px，无横向溢出。
- Ubuntu Hub 使用相对模块名读取锁文件，Node 报 MODULE_NOT_FOUND。改为绝对路径。
- 全新 Hub 直接绑定 0.0.0.0 被上游拒绝。启动器先只绑定本机，检测到有效管理员后允许团队访问，不放宽上游认证。
- Windows 非管理员能够打开 Hub 控制台，但创建 Local runtime 返回 503。启动入口现在明确处理管理员权限，而不是警告后假装可用。
- Ubuntu uv Python 的 minor-version 符号链接不在 bubblewrap 挂载白名单内，隔离运行时报解释器不存在。安装脚本将自身 venv 的解释器链接规范化为真实路径，不扩大沙箱文件系统权限。
- 安装器 Node 版本检查原来只打印 false 而不返回失败。已修正为真实退出码检查。
- 安装器升级解压保留已有 Hub 配置和工作区文件；路径穿越直接失败。
- 桌面启动器停止实例时存在未定义 `$root`，以及归属检查异常时放行的问题，已改为自身安装路径匹配与失败关闭。
- 单机诊断 `--check` 不再触发旧实例停止；重复安装不再安装已解耦的 Creator 依赖。
