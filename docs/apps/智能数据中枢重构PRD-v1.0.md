# 智能数据中枢重构 PRD v1.0

日期：2026-09-20
目标：把当前静态、不可查询的经营看板改造成可验证的订单节点监控与数据融合中枢。

## 用户问题

- 订单进度只有签收/在途/未发货，无法定位计划、加工、质检、发货卡点。
- 数据是静态快照，无法按订单、节点、生产小组查询。
- ERP、MES、WMS、OA、Excel 数据已经进入计算副本，但用户看不到数据链路和同步状态。
- 趋势图只显示 WC02，无法确认其它生产小组是否接入。

## V1 验收标准

1. 订单流程按计划、加工、质检、发货、签收展示完成率、进行中、未开始和超时数。
2. 超时规则使用 `stage_nodes.planned_end_at < snapshot_at` 且节点未完成；红色标识必须可解释。
3. 支持订单号搜索、节点筛选、生产小组筛选，并通过只读 SQL API 返回结果。
4. 查询结果至少展示订单号、节点、节点状态、计划结束时间、实际结束时间和超时标识。
5. 显示 ERP、MES、WMS、OA、Excel、WeChat 同步状态和记录数；不得把待 OCR 数据伪装成成功。
6. 人效趋势必须展示已接入的生产小组列表，并明确当前指标口径。
7. 数据为空、接口失败或 OCR 未完成时必须显示明确状态，不显示虚构数据。

## 数据与安全

- 只读访问 `agent_data.sqlite` / `/api/sql`，不修改业务数据。
- 查询参数只允许固定字段和转义后的搜索词，默认 LIMIT 200。
- 保留快照时间和数据来源，所有指标可追溯到表或配置。

## 本次执行范围

- 改造 `datahub-dashboard.html`：流程节点、融合指标、筛选查询、同步状态、错误状态。
- 保留旧 HTML 备份，使用真实 `stage_nodes`、`ingestion_runs` 和 `/api/sql` 数据。
- 后续 V2：实时轮询、权限控制、微信 OCR 接入、生产小组趋势图切换。
