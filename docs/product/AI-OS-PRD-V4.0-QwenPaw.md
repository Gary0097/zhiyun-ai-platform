# 智造云企业 AI-OS PRD V4.0

> 技术基线：QwenPaw `release/v2.1.0`  
> 文档状态：重构基线  
> 更新日期：2026-08-21  
> 替代范围：AI-OS PRD V3.x 中所有基于 DeepSeek Harness 的目标架构与后续实施计划

## 1. 产品决策

智造云企业 AI-OS 不再基于 DeepSeek Harness 继续重构。产品改为以 QwenPaw 2.1.0 为 Agent OS 内核、主对话界面和应用运行容器，以现有企业平台为业务数据与管理控制面。

本次变更不是更换模型或聊天组件，而是更换产品运行底座：

- QwenPaw 负责对话、会话连续性、记忆、Agent Loop、Skills、Plugins、MCP、文件工作区、定时任务、多 Agent、Sandbox 与 Tool Guard。
- 智造云企业服务负责租户、用户、组织、业务数据、业务规则、企业审计、风险熔断和统计。
- 企业核心模块通过 PawApp 形成真正可运行的应用，通过 Tool/MCP 调用企业服务。
- 品牌通过配置和插件插槽覆盖，不直接散改上游代码。
- 原 DSH 适配器、iframe 对话和 DSH Session 路线停止新增功能，迁移完成后删除。

## 2. 现状问题

### 2.1 核心 AI 对话未达到验收要求

当前对话只是附加在企业后台旁边的入口，没有成为系统统一操作面，存在以下问题：

- 会话与企业任务、文件、知识、业务对象之间没有稳定上下文。
- 刷新、切换页面或长任务后，用户难以连续完成同一目标。
- 工具执行过程、阶段结果、错误、停止和恢复表达不完整。
- 对话结果大量停留在文本，没有可靠形成业务数据、文件或应用状态。
- 功能入口与对话割裂，用户不知道一句话能调用哪些真实能力。
- 演示依赖预制内容，不能证明真实模型、真实 Tool 和真实业务闭环。

### 2.2 功能演示未达到验收要求

当前“功能清单”偏展示页面，不等于可用应用：

- 不具备明确输入、执行状态、结构化输出和产物下载。
- 页面数据、AI 回复、后台记录之间缺少一致性校验。
- 无法重复运行相同场景并得到可追踪的新 Execution。
- 失败、超时、模型未配置、Tool 被阻断时缺少用户可理解的反馈。
- 演示不能从聊天直接发起，也不能在应用中继续与 Agent 协作。

## 3. 产品目标

V4.0 的验收目标只有四项：

1. **对话能完成任务**：用户通过自然语言创建、执行、追踪并继续一个真实任务，而非只获得回答。
2. **模块能作为应用运行**：每个核心模块都有独立 PawApp，可输入、可执行、可产出、可追踪。
3. **品牌可自主配置**：Logo、产品名、主色、登录页、桌面和应用图标可由管理员配置，升级上游版本时不丢失。
4. **演示可重复验收**：每个演示使用明确测试数据和脚本，连续运行不会串租户、串会话或复用伪结果。

## 4. 非目标与边界

- 本期不自行重写 QwenPaw 的 Agent Loop、记忆、文件工作区、插件市场和桌面窗口系统。
- 本期不建设独立 Capability 权限产品，也不建设 Approval 审批中心。
- 高风险操作继续采用：无人值守禁止、交互确认、租户熔断、限流、参数校验和不可变审计。
- 不把现有企业后台整体塞入 iframe。
- 不以静态 Mock、写死回复或预生成截图作为功能验收。
- 不承诺所有旧页面原样迁移；仅迁移有真实业务价值且能闭环验收的模块。

## 5. 用户与使用场景

| 角色 | 核心诉求 | 默认入口 |
| --- | --- | --- |
| 企业员工 | 用对话或应用完成日常业务任务 | AI 对话、桌面应用 |
| 业务负责人 | 查看任务进度、结果和异常 | 任务中心、业务 PawApp |
| 企业管理员 | 配置品牌、模型、应用和组织 | 系统设置 |
| 审计人员 | 查询执行、Tool 和风险记录 | AI-OS 监视器 |
| 平台运维 | 部署、升级、备份和故障诊断 | 运维接口与日志 |

## 6. 总体架构

```text
用户
  │
  ▼
QwenPaw Console / OS Shell / PawApp
  ├─ Chat & Session
  ├─ Memory & Files
  ├─ Skills / Plugins / Cron
  └─ Sandbox / Tool Guard
  │
  ├─ PawApp Backend
  └─ Enterprise MCP / Tool Gateway
             │
             ▼
智造云企业服务
  ├─ Tenant / Identity / Business Data
  ├─ Knowledge / Task / Project / Artifact
  ├─ Risk Control / Audit / Trace
  └─ Existing Enterprise APIs
```

### 6.1 组件职责

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| QwenPaw Runtime | Agent Loop、上下文、记忆、会话、工具编排、长任务 | 企业业务规则与主数据 |
| QwenPaw Console | 主对话、OS 桌面、文件、设置、应用容器 | 旧后台页面兼容 |
| 企业品牌插件 | Logo、名称、主色、品牌资源和默认应用 | 修改 QwenPaw 核心协议 |
| 企业 PawApp | 业务模块 UI、项目状态、AgentDock、产物展示 | 跨应用直接读数据库 |
| Enterprise Gateway | 租户映射、API/Tool/MCP、风险控制、审计 | 对话界面 |
| 企业服务 | 业务数据、规则、统计、租户和审计 | Agent 会话存储 |

### 6.2 上游策略

- 固定基线为 `agentscope-ai/QwenPaw@release/v2.1.0`。
- 保留 Apache-2.0 LICENSE、NOTICE 和上游归属。
- 智造云扩展优先使用 Plugin、PawApp、Slot、配置和 API；只有无法扩展的缺口才维护最小补丁。
- 每次升级先执行上游契约测试、品牌测试、聊天验收和全部应用 E2E。

## 7. 品牌定制

### 7.1 管理员配置项

| 配置 | 要求 |
| --- | --- |
| 产品名称 | 支持中文名、英文名和浏览器标题 |
| Logo | 浅色、深色、方形图标、favicon，支持 PNG/SVG |
| 主色 | 支持浅色/深色主题下的主色与强调色 |
| 登录页 | 标题、副标题、背景、帮助链接 |
| OS 桌面 | 壁纸、启动画面、菜单栏品牌、Dock 默认应用 |
| 应用品牌 | PawApp 名称、图标、简介和排序 |

### 7.2 实现约束

- 默认通过 QwenPaw `header.logo`、`header.leftLogo`、`header.leftTitle`、`theme.colorPrimary` 等扩展插槽实现。
- 品牌资源保存于独立配置目录，不写入构建产物。
- Logo 上传后立即预览；保存后刷新和重启均保持。
- 文件类型、尺寸和 SVG 安全性必须校验。
- 任何页面不得再次出现硬编码 QwenPaw 或旧 DSH 产品名；许可证与关于页面中的上游声明除外。

### 7.3 验收

1. 管理员上传四类 Logo 并修改产品名和主色。
2. 登录页、顶部、OS 启动画面、桌面和浏览器图标同步变化。
3. 重启服务后配置不丢失。
4. 升级 QwenPaw 小版本后品牌配置仍生效。
5. 非管理员无法修改品牌。

## 8. AI 对话验收标准

AI 对话是 V4.0 第一优先级，以下条件必须全部满足。

### 8.1 基础对话

- 首 token 可见，不使用整段等待后一次性显示。
- 用户能停止正在生成的回复。
- Markdown、表格、代码、图片、文件和 Tool 卡片正确渲染。
- 模型未配置、密钥错误、限流、超时分别给出可操作提示。
- 新建、重命名、继续、删除会话行为稳定。

### 8.2 连续任务

- 同一会话连续 20 轮，仍能引用前序用户目标、文件和业务对象。
- 页面刷新、服务重启后可继续会话。
- 长上下文由 QwenPaw Scroll Context/记忆机制接管，不自行拼接超长 Prompt。
- 用户切换应用后返回对话，任务和产物引用不丢失。

### 8.3 Tool 与业务执行

- 用户可从对话发起一个核心业务应用任务。
- Tool 调用必须显示：名称、关键输入、运行状态、结果摘要和 Trace ID。
- 读取类 Tool 可直接执行；高风险写 Tool 执行现有风险控制。
- Tool 失败时保留已完成步骤并允许用户重试，不得伪造成功。
- 成功结果必须至少形成一种可验证产物：数据库记录、文件、任务状态或应用项目。

### 8.4 文件与知识

- 用户可上传 PDF、Word、Excel、图片和文本，并在同一会话引用。
- 回答企业知识问题时给出来源文件或记录定位。
- 找不到依据时明确说明，不允许用模型常识冒充企业数据。
- 产出文件可预览、下载，并记录创建它的会话和 Execution。

### 8.5 性能门槛

| 指标 | 验收门槛 |
| --- | --- |
| 页面打开 | P95 ≤ 3 秒（局域网基准环境） |
| 普通对话首 token | P95 ≤ 5 秒，不含模型供应商超时 |
| Tool 状态反馈 | 调用开始后 1 秒内出现运行态 |
| 停止操作 | 点击后 2 秒内停止继续输出 |
| 会话恢复 | P95 ≤ 3 秒加载最近消息，历史可渐进加载 |
| 错误可解释率 | 100% 返回用户可读原因与下一步 |

## 9. 核心应用模型

### 9.1 应用定义

核心功能模块不得只做菜单和静态页面。每个模块必须封装为 PawApp，并至少包含：

- `plugin.json`：应用标识、版本、图标、入口、依赖和权限。
- Frontend：项目/任务界面、输入、状态、产物与 AgentDock。
- Backend：应用 API、项目状态和与企业 Gateway 的交互。
- Agent Contract：目标、可用 Tool、输入输出 Schema、停止和恢复行为。
- Demo Fixture：可重复初始化的租户样例数据。
- E2E：从输入到产物的自动化验收脚本。

### 9.2 第一批核心应用

| 优先级 | PawApp | 真实输入 | 必须产出 |
| --- | --- | --- | --- |
| P0 | 企业 AI 对话 | 自然语言、文件、业务对象 | 回复、Tool 记录、文件/任务产物 |
| P0 | 任务与项目中心 | 目标、截止时间、附件 | Task、Execution、Checkpoint、Artifact |
| P0 | 企业知识助手 | 文件、知识库、问题 | 带来源答案、引用、知识更新记录 |
| P0 | AI-OS 监视器 | 当前租户运行数据 | KPI、执行、风险、Trace |
| P1 | 邮件营销数字员工 | 产品、市场、联系人、素材 | 宣传内容、邮件草稿、发送任务与日志 |
| P1 | 售前报价数字员工 | 客户需求、产品配置、价格规则 | 配置清单、报价草案、正式文档 |
| P1 | 售后工单数字员工 | 客户消息、设备、知识与工单 | 答复、工单、转人工记录、服务报告 |
| P1 | 财务票据数字员工 | 发票、回单、查询条件 | 识别记录、原件索引、查询结果与报表 |

### 9.3 应用与对话协同

- 从聊天可创建应用项目，并打开对应 PawApp。
- PawApp 中当前选中记录、文件、时间范围可作为 Agent 上下文。
- 应用执行完成后把结构化摘要和 Artifact 回写当前会话。
- 同一项目再次打开时恢复状态，不重新生成假结果。
- 应用可以独立运行，但不得绕过统一 Trace 和风险控制。

## 10. 功能演示验收

### 10.1 演示的定义

一次合格演示必须形成以下闭环：

```text
清晰输入 → 创建真实任务 → Agent/Tool 实际执行 → 状态可见
→ 生成结构化结果/文件 → 写入业务记录 → Trace 可回放 → 可再次运行
```

### 10.2 禁止项

- 写死 AI 回复、随机填充结果或前端假进度。
- 点击模块只显示介绍文案。
- 结果只存在浏览器内存，刷新后消失。
- 后台失败但前端显示成功。
- 所有演示共享同一个固定 Session 或固定 Trace。
- 使用 `simulated` 数据时不显示数据来源。

### 10.3 每个应用的验收包

每个核心应用交付时必须同时提供：

1. 演示目标与用户故事。
2. 初始化数据脚本和数据来源标记。
3. 3–5 分钟人工演示脚本。
4. Happy Path E2E。
5. 至少三种失败路径：模型错误、Tool 错误、业务校验失败。
6. 产物与数据库记录核验说明。
7. Trace ID 和审计记录核验说明。

### 10.4 总体验收门槛

- P0 应用通过率 100%。
- P1 应用通过率 ≥ 95%，不得存在数据错写或跨租户问题。
- 连续演示 10 次不得出现固定答案复用、会话串线和重复脏数据。
- 重新启动后，已完成项目、会话和文件仍可打开。

## 11. 多租户与身份

- QwenPaw 用户/Agent/Session 必须映射到企业 `tenant_id` 和 `user_id`。
- 企业 Tool Gateway 不接受前端自行提交的可信 `tenant_id`；租户由服务端身份解析。
- 每个租户使用隔离工作区、会话命名空间、应用存储和企业数据过滤。
- 平台管理员跨租户查看必须走专用管理接口并写审计，不复用普通用户 Tool。
- 跨租户读取、写入、文件引用和 Session 续接都必须有自动化反向测试。

## 12. 高风险操作控制

本版本不引入 Capability 管理与 Approval 审批中心，但必须保留以下控制：

- 无人值守任务默认禁止敏感写操作。
- 交互式敏感写操作显示轻量确认卡。
- 租户级写操作熔断开关。
- 每租户写操作频率限制。
- 参数大小、嵌套、危险键和业务范围校验。
- QwenPaw Tool Guard/Sandbox 负责系统工具安全；企业 Gateway 负责业务写安全。
- 允许与阻断均记录 user、tenant、session、execution、tool、参数摘要、原因码和 Trace。

## 13. 数据、Trace 与可观测性

- QwenPaw Session ID 与企业 Task/Execution 建立关联，不复制完整会话正文到企业库。
- 每次 Agent 任务、Tool 调用、应用运行和 Artifact 生成共享 Trace ID。
- AI-OS 监视器展示 QwenPaw 运行状态和企业执行状态的统一只读视图。
- 日志不得记录 API Key、Cookie、Authorization、完整敏感参数和文件正文。
- 支持按 Session、Task、Execution、Tool、Artifact 查询链路。

## 14. 迁移策略

### 14.1 保留

- 企业租户、用户、业务表和业务 API。
- WorkTask/Project/Artifact/Execution/Checkpoint 领域模型。
- 高风险 Tool 控制和不可变审计。
- AI-OS 监视器中的企业运行数据。
- 已验证的业务 Tool 和数据生成器，但必须重新接入 Gateway。

### 14.2 替换

| 旧实现 | 新实现 |
| --- | --- |
| DSH iframe 对话 | QwenPaw 原生 Chat/OS Shell |
| DSH Session API 适配器 | QwenPaw Session 与 Agent Runtime |
| 自建轻量 Agent Loop 主路径 | QwenPaw Agent Loop |
| 功能入口 chips/静态演示 | 可安装、可运行 PawApp |
| KNOWLEDGE.md 单向导出 | QwenPaw Files/Memory + 企业知识 Tool |
| 页面内品牌硬编码 | 品牌插件与配置 |

### 14.3 退出

- 停止开发 `dsh` Runner 新功能。
- 新应用不得依赖 DSH HTTP 信封、`events.mux` 或 DSH 工作区路径。
- 完成对话、任务和定时任务迁移后移除 DSH 启动依赖。
- 删除前先保留一个只读迁移工具，将必要 Session 摘要、文件和 Trace 关联导出。

## 15. 分阶段实施

### Phase Q0：架构转向与可运行基线

- 提交本 PRD、迁移 ADR、QwenPaw 版本锁定和许可证说明。
- 建立 QwenPaw 本地开发/容器启动方式。
- 建立企业扩展目录，不修改上游核心代码。
- 完成品牌插件最小样例和健康检查。
- 冻结 DSH 新功能。

**退出标准**：一条命令同时启动 QwenPaw 和企业服务，健康检查明确显示两个服务及版本。

### Phase Q1：品牌与主对话

- 管理员可配置 Logo、名称、主色和登录页。
- 替换现有 AI 对话为 QwenPaw 原生 Chat。
- 完成模型配置、流式输出、停止、会话恢复和错误提示。
- 接入第一个只读企业 Tool。

**退出标准**：AI 对话章节全部 P0 验收通过，聊天不再依赖 DSH。

### Phase Q2：企业 Gateway 与统一执行

- 建立 QwenPaw 身份到企业租户的可信映射。
- 业务 Tool/MCP 接入统一 Trace、风险控制和审计。
- Task/Execution/Artifact 与 QwenPaw Session 关联。
- 迁移知识检索和文件产出。

**退出标准**：从对话创建真实 Task、调用 Tool、生成 Artifact，并能在监视器回放。

### Phase Q3：P0 PawApp

- 任务与项目中心。
- 企业知识助手。
- AI-OS 监视器。
- 每个应用具备 Demo Fixture、E2E 和失败路径。

**退出标准**：P0 应用演示连续运行 10 次全部通过。

### Phase Q4：P1 业务数字员工

- 邮件营销、售前报价、售后工单、财务票据按优先级迁移。
- 应用支持项目状态、AgentDock、结构化产物和下载。
- 完成业务数据核验和性能测试。

**退出标准**：至少两个完整业务应用达到生产试点标准，其余模块不得用静态演示替代。

### Phase Q5：清理与发布

- 移除 DSH 运行依赖、旧 iframe 和重复 Agent Loop。
- 完成数据迁移、备份恢复、升级测试和部署文档。
- 完成安全、租户隔离和许可证检查。

**退出标准**：生产部署不启动 DSH，所有核心验收基于 QwenPaw 路径完成。

## 16. 发布阻断条件

出现以下任一情况不得发布：

- AI 对话无法稳定流式输出、停止或恢复会话。
- 核心应用没有真实产物或刷新后结果丢失。
- 演示依赖写死回复或假进度。
- 任何跨租户读写、文件或会话串线。
- 高风险写操作绕过企业 Gateway。
- Logo/品牌只能改源码，无法通过配置持久化。
- QwenPaw 版本未锁定或 Apache-2.0 归属缺失。
- DSH 与 QwenPaw 同时消费同一任务造成重复执行。

## 17. 完成定义（Definition of Done）

一项功能只有同时满足以下条件才算完成：

- 需求、输入、输出和错误路径明确。
- 通过租户隔离、风险控制和 Trace 约束。
- 有自动化测试和可重复演示脚本。
- 使用真实模型/Tool 时能证明实际调用；使用模拟数据时明确标记。
- 结果能够持久化、恢复、下载或被后续任务引用。
- 页面不是功能介绍，而是可完成工作的应用。
- 文档、部署、回滚和运维说明同步更新。

## 18. 首轮验收场景

用户登录后，把一份产品资料和客户需求上传到 AI 对话，要求“整理需求、查询企业产品知识、创建售前任务并输出报价草案”。系统必须：

1. 流式理解并展示执行计划。
2. 读取上传文件并给出来源引用。
3. 调用企业知识只读 Tool。
4. 创建真实企业 Task 与 Execution。
5. 生成可下载报价草案 Artifact。
6. 在聊天中返回摘要和应用入口。
7. 在任务中心看到状态，在监视器看到 Trace。
8. 刷新或重启后仍能继续该会话和项目。
9. 对涉及正式报价写入的动作执行高风险控制。
10. 全流程不依赖 DSH、不使用固定回复或预生成结果。
