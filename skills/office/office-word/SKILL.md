# 办公技能 · Word 文档

## 1. 环境自检（办公版已预装，直接用）

python-docx 已由启动器预装，不要在对话中重复安装；仅 import 报缺失时才补装：

```bash
python -c "import docx; print(docx.__version__)"    # 缺失时: pip install python-docx
soffice --version   # 可选：.doc 转换 / 导出 PDF
```

- 生成与编辑 .docx 首选 **python-docx**；抽取纯文本可配合 `python -m markitdown`。

## 2. 文档先讲结构，再讲字

动笔前先产出**层级大纲**（章 → 节 → 每节要点）并与用户确认；超过 3 页的文档
必须先确认大纲。正文遵守：

- 一级标题不超过 7 个；同层标题句式一致（都是名词短语或都是问句，不混用）；
- 段落 3–6 行为一个单元，一段一个意思；能列表的并列内容就用列表；
- 中文公文/正式文档：标题黑体、正文宋体/仿宋小四或五号、1.5 倍行距、首行缩进两字符；
  通用商务文档：标题加粗同级同字号，正文统一字体，全文不超过两种字体。

## 3. 样式体系（不要直接刷格式）

用 Word **样式**（Heading 1/2/3、正文）组织文档，而不是逐段手动设字体：

- python-docx 中修改 `styles['Heading 1']`、`styles['Normal']` 的字体/字号/间距，
  全文自动继承；中文字体需同时设置 `w:eastAsia` 属性；
- 标题用样式后，可在引用位置插入自动目录（`TOC` 域），打开时按 F9 更新；
- 页眉页脚统一通过节（section）设置；正式文档页脚加"第 X 页 共 Y 页"域。

## 4. 标准工作流

1. **输入盘点**：确认文种（请示/报告/方案/合同/纪要）、称谓对象、篇幅、必备要素。
   公文有固定要素（标题、主送、正文、落款、日期），先列模板再填内容。
2. **内容来源**：事实与数据来自用户材料或 `office-research` 的检索结果，
   引用要可溯源；用户没给又查不到的信息，明确标注"待补充"，不要编造。
3. **脚本生成**：写 Python 脚本创建文档（结构 + 样式 + 内容），可重跑可改稿；
   表格用 `add_table` 并套用表格样式；图片先下载到本地再 `add_picture`，
   控制宽度不超过版心。
4. **编辑既有文档**：原件只读，先复制 `<原名>_工作副本.docx`；批量替换/改格式
   写脚本遍历段落执行，完成后报告替换处数。
5. **导出 PDF**（可选）：LibreOffice `--convert-to pdf`；转换后抽查首页与目录页。

## 5. 交付前检查单

- [ ] 大纲层级与标题句式一致，目录（如有）与正文标题一致；
- [ ] 字体字号全篇统一，无手工散点格式；
- [ ] 表格无跨页断行错乱（关键行允许跨页时设置重复标题行）；
- [ ] 数字、日期、称谓、落款已核对；没有编造的事实，待确认处已标注；
- [ ] 交付文件命名 `主题_v1.docx`，改稿递增版本号，不覆盖原件；
- [ ] 需要配图处已用 `office-image-search` 取图并确认使用许可。
