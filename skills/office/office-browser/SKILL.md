# 办公技能 · 浏览器操控

## 1. 使用原则

- 网页内的任务**一律用本技能**；本地文件与程序操作转 `office-computer`。
- 遵循 **感知 → 操作 → 验证** 循环：每一步操作前先观察页面当前状态，
  操作后截图/读取 DOM 确认结果，再决定下一步。禁止"盲操作"——
  不看页面就连点带填是错误率最高的做法。
- 每次会话结束前，用一句"已到达的最终页面/完成的结果"收尾验证。

## 2. 工具调用方式

运行时的 `browser` 工具接收一段异步 Python 代码，使用统一浏览器 SDK
（浏览器上下文、页面对象）。编写代码时：

1. 打开/复用页面 → 2. `await` 页面加载 → 3. 读取标题/URL/关键元素确认到达
   → 4. 填写或点击 → 5. 再次读取确认结果。

```python
# 典型骨架（具体 API 以运行时内置 browser 技能文档为准）
page = await browser.new_page()          # 或复用当前页
await page.goto("https://example.com")   # 感知
title = await page.title()               # 确认到达
await page.click("text=登录")            # 操作
await page.screenshot(path="结果.png")   # 验证
```

若技能池中存在内置 `browser` 技能，先读取其最新用法说明再编码，
SDK 细节以内置文档为准。

## 3. 高频任务流程

### 信息浏览与网页查证

1. 打开目标页 → 截图/提取正文 → 与用户问题对照；
2. 需要多个来源时开多页并行处理，逐页记录 URL 与要点；
3. 输出结论时附来源链接（与 `office-research` 技能配合）。

### 自动填表

1. 先**无操作预览**：读取表单全部字段与必填标记，向用户复述将要填写的内容；
2. 涉及密码/验证码/支付/人脸的页面，停下来让用户手动完成这些字段
   （绝不代填敏感凭据，绝不绕过人机验证）；
3. 提交前截图留档，提交后再截图确认成功页。

### 批量抓取

1. 先在 1–2 页上跑通"打开 → 提取 → 翻页"循环，给用户看样本数据确认字段；
2. 全量执行加延时（每页 1–3 秒随机间隔），失败重试不超过 2 次并记录；
3. 结果边抓边落盘（CSV/JSON），中断可续跑；
4. 只抓取允许抓取的公开内容，遵守目标站点服务条款；登录态数据仅限用户
   明确授权的自己的账号内容。

### 文件下载

触发下载后等待完成事件，确认文件落盘路径与大小 > 0 再报告成功。

## 4. 出错处理

| 现象 | 处理 |
|------|------|
| 元素找不到 | 先截图看实际页面；可能弹窗/未登录/改版，调整选择器或改用语义定位 |
| 页面加载慢 | 延长等待或改用网络空闲判断，不盲目重试 |
| 登录过期 | 停下告知用户需要重新登录，不自动尝试绕过 |
| 反爬拦截 | 降低频率、减少并发；仍被拦截则停止并如实报告，不伪装规避 |

## 5. 交付前检查单

- [ ] 每次关键操作前后都有页面状态证据（标题/URL/截图）；
- [ ] 填写过的重要字段已向用户复述；
- [ ] 敏感步骤（密码/验证码/支付）由用户手动完成；
- [ ] 抓取结果有来源 URL，样本已给用户确认；
- [ ] 最终结果一句话验证（"已在 XX 页面看到 XX 状态"）。
